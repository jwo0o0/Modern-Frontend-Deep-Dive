## 5.2 리액트 훅으로 시작하는 상태 관리

### 가장 기본적인 방법: useState와 useReducer

`useState`와 `useReducer`를 기반으로 하는 사용자 지정 훅의 한계

- 훅을 사용할 때마다 컴포넌트별로 초기화되므로 **컴포넌트에 따라 서로 다른 상태를 가질 수 밖에 없음**
- **컴포넌트별로 상태의 파편화**

→ 해결하려면? 지역 상태를 상위 컴포넌트로 끌어올려 전역 상태로 만듦

### 지역 상태의 한계를 벗어나 보자: useState의 상태를 바깥으로 분리하기

`useState`: 리액트가 만든 클로저 내부에서 관리되어 **지역 상태로 생성, 해당 컴포넌트에서만 사용 가능**

→ `useState`가 다른 자바스크립트 실행 문맥 어디에선가 초기화돼서 관리된다면?

- 이 방식의 가장 큰 문제: **컴포넌트가 리렌더링되지 않음**
  - 리액트의 렌더링 방식: 새로운 상태를 사용자의 UI에 보여주기 위해서는 반드시 리렌더링이 필요함

**📌 함수 외부에서 상태를 참조하고 이를 통해 렌더링까지 자연스럽게 일어나려면 만족해야 하는 조건**

- 컴포넌트 외부 어딘가에 상태를 두고 여러 컴포넌트가 같이 쓸 수 있어야 한다.
- 외부에 있는 상태를 사용하는 컴포넌트는 상대의 변화를 알아챌 수 있어야 하고 상태가 변화될 때마다 리렌더링이 일어나 최신 상태값 기준으로 렌더링해야 한다.
- 상태가 원시값이 아닌 객체인 경우에 그 객체에 내가 감지하지 않는 값이 변한다 하더라도 리렌더링이 발생해서는 안 된다.

### useState와 Context를 동시에 사용해 보기

💡 훅을 사용하는 서로 다른 스코프에서 스토어의 구조는 동일하되, 여러 개의 서로 다른 데이터를 공유해 사용하고 싶다면?

⇒ 리액트의 **Context**를 활용해 **해당 스토어를 하위 컴포넌트에 주입**

- 스토어를 사용하는 컴포넌트: 해당 상태가 어느 스토어에서 온 상태인지 신경 쓰지 않아도 됨
- useState, useReducer가 가지고 있는 한계, 컴포넌트 내부에서만 사용할 수 있는 지역 상태라는 점을 극복
