## 4.3 Next.js 톺아보기

### Next.js란?

💡 **Vercel**에서 만든 **풀스택 웹 애플리케이션을 구축하기 위한 리액트 기반 프레임워크**
PHP에 영감을 받아 만들어졌으며, 설계 당시부터 서버 사이드 렌더링을 염두에 두었음

### Next.js 시작하기

> *create-next-app*을 기반으로 빠르게 Next.js 기반 프로젝트를 생성할 수 있음

```bash
npx create-next-app@latest --ts
```

- **package.json**

  ```tsx
  {
    "name": "my-app",
    "version": "0.1.0",
    "private": true,
    "scripts": {
      "dev": "next dev",
      "build": "next build",
      "start": "next start",
      "lint": "next lint"
    },
    "dependencies": {
      "react": "^18",
      "react-dom": "^18",
      "next": "14.2.14"
    },
    "devDependencies": {
      "typescript": "^5",
      "@types/node": "^20",
      "@types/react": "^18",
      "@types/react-dom": "^18",
      "eslint": "^8",
      "eslint-config-next": "14.2.14"
    }
  }


  - `next`: Next.js의 기반이 되는 패키지
  - `eslint-config-next`: Next.js 기반 프로젝트에서 사용하도록 만들어진 ESLing 설정

  ```

- **next.config.json**

  ```tsx
  /** @type {import('next').NextConfig} */
  const nextConfig = {
    reactStrictMode: true,
    swcMinify: true,
  };

  export default nextConfig;
  ```

  - @type으로 시작하는 주석: 자바스크립트 파일에 타입스크립트의 타입 도움을 받기 위해 추가
  - `reactStrictMode`, `swcMinify` 모두 Next.13부터 Default

- **pages/\_app.tsx**
  > default export로 내보낸 함수는 **애플리케이션 전체 페이지의 시작점**이 됨
  - 웹 애플리케이션에서 공통으로 설정해야 하는 것들을 여기서 실행
    - 에러 바운더리를 사용해 애플리케이션 전역에서 발생하는 에러 처리
    - reset.css 같은 전역 CSS 선언
    - 모든 페이지에 공통으로 사용 또는 제공해야 하는 데이터
- **pages/\_document.tsx**
  > 애플리케이션의 **HTML을 초기화하는 곳**
  - 없어도 실행에는 지장이 없는 파일
  - <html>이나 <body>에 DOM 속성을 추가하고 싶다면 사용
  - `_app.tsx`는 렌더링이나 라우팅에 따라서 서버나 클라이언트에서 실행되지만, `_document`는 무조건 서버에서 실행
  - CSS-in-JS의 스타일을 서버에서 모아 HTML로 제공하는 작업
- **pages/\_error.tsx**
  > 클라이언트에서 발생하는 에러 또는 서버에서 발생하는 500 에러를 처리
  - 개발 모드에서는 방문할 수 없고 프로덕션으로 빌드해서 확인해야 함
- **pages/404.tsx**
  > 404 페이지를 정의할 수 있는 파일
- **pages/500.tsx**
  > 서버에서 발생하는 에러를 핸들링
  - \_error.tsx보다 우선으로 실행
- **pages/index.tsx**
  > **웹 사이트의 루트**이며, localhost:3000과 같은 루트 주소를 의미함
  - 라우팅 구조는 `/pages` 디렉터리를 기초로 구성되며, 각 페이지에 있는 default export로 내보낸 함수가 해당 페이지의 루트 컴포넌트가 됨
    e.g. `/pages/hello.tsx` → [localhost:3000/hello](http://localhost:3000/hello로)로 접근할 수 있음
  - `/pages/hello/[greeting].tsx` : []의 의미는 어떠한 문자도 올 수 있음
  - `/pages/hi/[…props].tsx` : /hi를 제외한 하위의 모든 주소가 여기로 옴

### 서버 라우팅과 클라이언트 라우팅의 차이

💡 Next.js는 **서버 사이드 렌더링**을 수행하지만 동시에 SPA와 같이 **클라이언트 라우팅 또한 수행함**

- `next/link`
  > Next.js에서 제공하는 라우팅 컴포넌트, <a /> 태그와 비슷한 동작
  - **<a /> 태그로 이동**: 페이지를 만드는데 필요한 모든 리소스를 처음부터 가져옴. 서버에서 렌더링을 수행하고 클라이언트에서 hydrate
  - **next/link로 이동**: 서버 사이드 렌더링이 아닌 클라이언트에서 필요한 자바스크립트만 불러온 뒤 라우팅
    ⇒ Next.js의 장점을 살리기 위해서는 가급적 <Link>와 router.push를 사용
- `getServerSideProps`가 없으면 Next.js가 **서버에서 실행하지 않아도 되는 페이지로 처리**하고 빌드 시점에 미리 만들어도 되는 페이지로 간주함

### Data Fetching

Next.js에서는 pages/ 폴더에 있는 라우팅이 되는 파일에서 예약어로 지정되어 정해진 함수명으로 export를 사용해 데이터를 불러올 수 있다.
→ 서버에서 필요한 데이터를 가져와 미리 필요한 페이지를 만들어 제공할 수 있음

### 스타일 적용하기

1. **전역 스타일**

   `_app.tsx`에 필요한 스타일을 직접 import 하면 애플리케이션 전체에 적용할 수 있다.

2. **컴포넌트 레벨 CSS**

   `[name].module.css` 와 같은 명명 규칙으로 추가할 수 있음

   ```tsx
   import styles from './Button.modules.css'

   export function Button() {
   	return (
   		<button type="button" className={styles.alert}>
   			경고
   		</button>
   ```

3. SCSS와 SASS

   sass 패키지를 설치해서 사용 가능

4. CSS-in-JS

   리액트 트리 내부에서 사용하고 있는 styled-components의 스타일을 모두 모은 다음, 각각의 스타일에 유니크한 클래스명을 부여해 서버에서 렌더링할 때 React.Context 형태로 제공하는 코드가 필요

   → 위 과정이 없다면 FOUC(flash of unstyled content)를 잠시간 노출하게 됨

### next.config.js 살펴보기

```tsx
/**
 * @type {import('next').NextConfig}
 */
const nextConfing = {
  // 설정
};

modules.export = nextConfig;
```

- `basePath`: 클라이언트 렌더링을 트리거하는 모든 주소에서 bashPath가 붙은채로 작동
- `swcMinify`: swc를 이용해 코드를 압축할지 나타냄 (기본값 true)
- `poweredByHeader`: false를 선언하면 응답헤더에서 정보가 사라짐.
- `redirects`: 특정 주소를 다른 주소로 보내고 싶을 때 사용
- `reactStrictMode`: 리액트에서 제공하는 strict mode를 사용할지 여부(기본값 false)
- `assetPrefix`: 빌드된 결과물을 CDN 등에 업로드하고자 한다면 해당 CDN 주소를 명시
